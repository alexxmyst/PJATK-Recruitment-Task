Catalogue quality challenge: a team walkthrough¶

We want to spot listings with an injected catalogue error. The useful question turned out to be:

Given the product in the text, how plausible are the category, quantity, price and weight?

This notebook walks through the working approach with the code next to each explanation. It keeps the modelling and validation from the full pipeline, while leaving out the command-line interface, model packaging and most reporting utilities. The displayed results come from executing these cells.

The target is 0 for no controlled corruption and 1 for one controlled corruption. A target of 0 still allows missing values, discounts and legitimate alternative categories.

Reading route: data → facts from text → expected attributes → deviations → honest validation → results → submission.

Running it: keep this notebook in notebooks/ inside the project, use the environment from requirements-notebook.txt, and choose Restart Kernel and Run All Cells. It trains on CPU. The notebook does not need the catalogue_quality Python package: the essential functions are shown here. Original data and saved production models are preserved. Notebook-generated files go to outputs/notebook_walkthrough/ and are refreshed when the notebook is rerun.

1. Load the data¶

Each row is one offer. We have structured fields such as category and weight, plus a title and description. The test file has the same inputs but no target. The sample submission tells us the required output order.

The checks below catch overlapping IDs, overlapping sellers and invalid numeric values before training.

2. Turn the text into a few useful facts¶

These descriptions follow a small set of templates. For example, we can read Wired earbuds by Noro. Variant: compact. Included main items: 2. as three facts:

Fact Extracted value
Product phrase wired earbuds
Variant compact
Main-item quantity 2

We normalize case and whitespace, then use regular expressions to recognize the known templates. This is a small, task-specific form of NLP. We keep the raw text in the original tables for inspection. The final model uses extracted facts rather than raw-text TF-IDF vectors.

Quantity needs context. “3 pcs of free accessories” does not mean three main items. We search for main-item phrases first and use the title when the description gives no main quantity.

In [4]:
MISSING = "__missing__"
CATS = ["declared_category", "brand", "condition", "product", "variant"]
NUMS = ["price_pln", "shipping_weight_kg", "pack_size"]
WORDS = {"one": 1, "two": 2, "three": 3, "five": 5}
COUNT = r"(\d+|one|two|three|five)"

def normalize(value):
    if pd.isna(value):
        return ""
    return re.sub(r"\s+", " ", unicodedata.normalize("NFKC", str(value)).lower()).strip()

def main_quantity(text, description=False):
    patterns = [
        rf"included main items:\s*{COUNT}", rf"package contains\s+{COUNT}\s+pcs",
        rf"bundle quantity:\s*{COUNT}\s+units", rf"sold as a\s+{COUNT}-pack",
        rf"pack of\s+{COUNT}\s+main items", rf"{COUNT}\s+individually boxed main items",
    ] if description else [
        rf"quantity\s+{COUNT}\b", rf"pack of\s+{COUNT}\b",
        rf"\b{COUNT}\s*(?:-pack|pcs|units|main items)\b",
    ]
    for pattern in patterns:
        match = re.search(pattern, normalize(text))
        if match:
            token = match.group(1)
            value = WORDS[token] if token in WORDS else int(token)
            return float(value) if value > 0 else np.nan
    return np.nan

The next function puts the extracted facts next to the structured inputs. It also adds:

  • The difference between the text quantity and pack_size.
  • Price and weight per declared item, and per item counted in the text.
  • Log values, which make multiplicative differences easier to model.
  • A few context flags, including promotions, accessories and numeric missingness.

We retain promotion wording because it can explain a legitimate low price. Unknown products and categories stay unknown. Seller IDs and listing IDs are never model features.

In [6]:
def make_features(df):
    x = df[["declared_category", "brand", "condition", *NUMS]].copy()
    title, desc = df.title.map(normalize), df.description.map(normalize)
    x["product"] = desc.str.extract(
        r"(?:^|\. )([^.]*) by (?:aster|mira|noro|tenso|velto)\.", expand=False)
    variant = desc.str.extract(r"variant:\s*(\w+)", expand=False).astype("string")
    fallback = title.str.extract(r"\b(standard|compact|large)\b", expand=False).astype("string")
    x["variant"] = variant.fillna(fallback)
    x["desc_quantity"] = desc.map(lambda s: main_quantity(s, description=True))
    x["title_quantity"] = title.map(main_quantity)
    x["main_quantity"] = x.desc_quantity.fillna(x.title_quantity)
    x["quantity_difference"] = x.pack_size - x.main_quantity
    x["title_desc_quantity_difference"] = x.title_quantity - x.desc_quantity
    x["clearance"] = desc.str.contains("clearance promotion", regex=False).astype(int)
    x["accessory"] = desc.str.contains("free accessory", regex=False).astype(int)
    x["title_length"], x["description_length"] = title.str.len(), desc.str.len()
    for col in NUMS:
        x[col + "_missing"] = df[col].isna().astype(int)
        x["log_" + col] = np.log(df[col])
    for col in ["price_pln", "shipping_weight_kg"]:
        x[col + "_per_declared_item"] = df[col] / df.pack_size
        x[col + "_per_text_item"] = df[col] / x.main_quantity
    for col in CATS:
        x[col] = x[col].fillna(MISSING).astype(str)
    return x.replace([np.inf, -np.inf], np.nan)

3. Learn what categories are normal for each product¶

A universal rule such as “headphones belong to audio” is too strict for this catalogue. Some uncorrupted headphone listings legitimately use computers. We learn those conventions from rows with target=0 instead.

For product p and declared category c, we calculate:

P(category=c | product=p) = (reference count for p,c + 1) / (all reference counts for p + K)
category_surprisal = -log(P(category=c | product=p))

K is the number of categories in the reference table. Adding 1 prevents a previously unseen pair from receiving zero probability and infinite surprise. A high score means the pairing is unusual; it is not directly the probability of corruption.

The next cell is an illustration using all target-0 rows. Its table is never used as a training feature. The actual models below build fresh reference tables inside each training partition.

4. Learn expected prices and weights¶

A price of PLN 200 means different things for an SSD, a mug and a pack of five items. We fit two ridge regressions on rows without controlled corruption: one predicts log price, and the other predicts log shipping weight. Ridge is a linear model with regularization to keep its estimates stable.

Inputs are product phrase, variant, brand, condition, text quantity and promotion status. Categorical inputs are one-hot encoded for these regressions. CatBoost later handles its categorical inputs directly.

We exclude the observed price from the price predictor, and the observed weight from the weight predictor. We also use the quantity extracted from text rather than the potentially corrupted pack_size. The model has to estimate what the value should look like from the surrounding information.

In [9]:
REF_CATS = ["product", "variant", "brand", "condition"]

def reference_inputs(x):
    inputs = x[REF_CATS + ["clearance"]].copy()
    inputs["log_main_quantity"] = np.log(x.main_quantity.fillna(1))
    return inputs

def fit_reference(x, labels):
    clean = x.iloc[np.flatnonzero(np.asarray(labels) == 0)]
    regressors = {}
    for column in ["price_pln", "shipping_weight_kg"]:
        observed = clean.loc[clean[column].notna()]
        preprocessing = ColumnTransformer([
            ("categories", OneHotEncoder(handle_unknown="ignore"), REF_CATS),
            ("numbers", "passthrough", ["clearance", "log_main_quantity"]),
        ])
        regression = make_pipeline(preprocessing, Ridge(alpha=2, solver="lsqr"))
        regression.fit(reference_inputs(observed), np.log(observed[column]))
        regressors[column] = regression
    known = clean.loc[clean['product'].ne(MISSING) & clean.declared_category.ne(MISSING)]
    counts = pd.crosstab(known['product'], known.declared_category)
    return regressors, counts

We turn each estimated value into three features: the expected log value, the signed deviation and the absolute deviation. The signed deviation tells us the direction; the absolute deviation tells us the size.

price residual = log(observed price) - predicted log price
               = log(observed price / expected price)

An observed price of 200 against an expected price of 100 gives a residual of about +0.693. A price of 50 gives about -0.693: both are a factor of two away.

Category surprisal joins these numeric deviations. When the product or declared category is unknown, its category score remains missing. Before the classifier, numeric missing values use -999 as a recognizable placeholder; categorical missing values use __missing__. The placeholder is not a measured value. If text quantity is unavailable, the reference regressions use 1 as a fallback; the classifier still sees that the parsed quantity is missing.

def reference_features(x, reference):
    regressors, counts = reference
    features = pd.DataFrame(index=x.index)
    for column, regression in regressors.items():
        expected = regression.predict(reference_inputs(x))
        residual = np.log(x[column]) - expected
        features[column + "_expected_log"] = expected
        features[column + "_residual"] = residual
        features[column + "_abs_residual"] = np.abs(residual)
    probabilities = []
    for product, category in zip(x['product'], x.declared_category):
        if product not in counts.index or category == MISSING:
            probabilities.append(np.nan)
        else:
            row = counts.loc[product]
            probabilities.append((row.get(category, 0) + 1) / (row.sum() + len(counts.columns)))
    features["category_surprisal"] = -np.log(probabilities)
    return features

def classifier_inputs(features):
    result = features.copy()
    for column in result:
        if column in CATS:
            result[column] = result[column].fillna(MISSING).astype(str)
        else:
            result[column] = result[column].replace([np.inf, -np.inf], np.nan).fillna(-999.)
    return result

5. Keep sellers out of their own validation data¶

Test sellers do not appear in training. Our validation needs to imitate that: all listings from a seller stay together in one of five outer folds.

There is a second leakage risk. Reference models use target=0 rows. If we calculated training features using a reference model that had already seen the same row, its label could influence its own features. We avoid that with three inner seller folds.

For one outer fold:
  Outer training sellers → split into 3 inner groups
  Each inner group gets reference features learned from the other groups
  Those features + outer training labels → train CatBoost

  All outer training sellers → fit the reference models for validation and test
  Held-out outer sellers → reference features → CatBoost predictions → score

Using known training labels to select reference rows is allowed. Held-out labels are used only to measure the resulting predictions. We do not use them for early stopping or hyperparameter selection. The five-fold assignment below matches the supplied baseline.

    for seller in train.seller_id

def inner_reference_features(x, labels, sellers):
    pieces = []
    labels, sellers = np.asarray(labels), np.asarray(sellers)
    for fit, held_out in GroupKFold(INNER_FOLDS).split(x, labels, sellers):
        assert set(sellers[fit]).isdisjoint(sellers[held_out])
        reference = fit_reference(x.iloc[fit], labels[fit])
        pieces.append(reference_features(x.iloc[held_out], reference))
    result = pd.concat(pieces).loc[x.index]
    assert result.index.equals(x.index) and len(result) == len(x)
    return result

6. Train the classifier¶

CatBoost combines all the signals and predicts the probability of controlled corruption. It can learn that a large quantity disagreement matters, that categories have different compatibility patterns, and that a numeric deviation needs context.

The settings match the working pipeline: 450 trees, depth 5, learning rate 0.05, regularization 5, seed 42 and four CPU threads. We keep them fixed for this report.

Every training row gets an out-of-fold (OOF) prediction from a model that held out its seller. Each fold also predicts the test set; we average those five probabilities for the submission.

In [12]:
oof = np.full(len(train), np.nan)
test_probability = np.zeros(len(test))
fold_scores, importance, held_out_references = [], [], []

for fold in range(N_FOLDS):
    fit, held_out = np.flatnonzero(fold_id != fold), np.flatnonzero(fold_id == fold)
    assert set(train.seller_id.iloc[fit]).isdisjoint(train.seller_id.iloc[held_out])
    fit_x, valid_x = X.iloc[fit], X.iloc[held_out]

    # Training features come from references that excluded each training seller.
    fit_ref = inner_reference_features(fit_x, y[fit], train.seller_id.iloc[fit])
    # Validation and test references see only the outer training partition.
    reference = fit_reference(fit_x, y[fit])
    valid_ref = reference_features(valid_x, reference)
    test_ref = reference_features(X_test, reference)

    model = CatBoostClassifier(iterations=450, depth=5, learning_rate=.05,
                               l2_leaf_reg=5, random_seed=SEED, thread_count=4,
                               loss_function="Logloss", verbose=False, allow_writing_files=False)
    model.fit(classifier_inputs(pd.concat([fit_x, fit_ref], axis=1)), y[fit], cat_features=CATS)
    oof[held_out] = model.predict_proba(
        classifier_inputs(pd.concat([valid_x, valid_ref], axis=1)))[:, 1]
    test_probability += model.predict_proba(
        classifier_inputs(pd.concat([X_test, test_ref], axis=1)))[:, 1] / N_FOLDS

    auc = roc_auc_score(y[held_out], oof[held_out])
    ap = average_precision_score(y[held_out], oof[held_out])
    fold_scores.append({"fold": fold + 1, "ROC-AUC": auc, "Average Precision": ap})
    importance.append(model.get_feature_importance())
    held_out_references.append(valid_ref)
    print(f"Fold {fold + 1}: ROC-AUC={auc:.6f}, AP={ap:.6f}")

9. Check the weak spots¶

A strong overall score can hide a weak subgroup. Product identity currently comes from the description. When descriptions are missing, that identity is unknown and reference estimates become much less specific. The table below compares these two groups using their held-out predictions.

This is the main limitation of the current implementation. Recovering product identity from titles, including synonym handling, is the next targeted improvement.

What to say when walking the team through it¶

We first extract product facts from the listing text. Then we use training rows without injected errors to learn the catalogue's normal category choices and expected prices and weights. We turn departures from those expectations into features and let CatBoost combine them with quantity checks and the original structured fields.

The key contribution is the learned reference, rather than a universal rule for what every product must look like. Validation holds out entire sellers, with a second layer of seller splitting to prevent the reference features from using a row's own label.

The results are local validation results, not a Kaggle score. The descriptions are synthetic and templated, and future wording or unseen product families may behave differently. The missing-description subgroup shows why we need to examine coverage and errors alongside the headline score.

The research that informed the approach:

  • Amazon PatternRAG: use similar catalogue entries to infer attributes.
  • Robust variational autoencoders for mixed-type data: learn normal relationships and identify corrupted cells. Our implementation uses simpler regressions and a supervised classifier.
